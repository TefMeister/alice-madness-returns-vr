Method: unpack a COPY with Steamless v3.1.0.5 (SteamStub Variant 3.1 x86), then
scan the UNPACKED .text only for `push imm32` (0x68) of each NVAPI dispatch id.
The still-packed copy is retained as a negative control.

could not have produced a positive, which is exactly the false-negative the

All six live references sit in ONE 825-byte function:
  0x00E65663  push 0x0150E828   ; NvAPI_Initialize
  0x00E657DC  push 0xAC7E37F4   ; Stereo_CreateHandleFromIUnknown
  0x00E6585C  push 0xF6A1AD68   ; Stereo_Activate

(addresses are in the UNPACKED image; the packed image's .text is encrypted so
they do not correspond to on-disk addresses of the shipped exe)

Shape: init -> create handle -> activate -> read separation, convergence and eye
separation. Three GETTERS and no setters at all; SetSeparation is 0 here where
Alan Wake had 1.

VERDICT: AUTOMATIC. Both Direct-only discriminators have zero references while
the Automatic-side witnesses are all present. The game activates stereo and then
READS BACK what the driver decided; it never sets driver mode or active eye, so
it never takes the eyes off the driver.

Regenerating: this needs the unpacked binary, which is GAME CONTENT and is
deliberately NOT committed. To reproduce, unpack a copy again:
